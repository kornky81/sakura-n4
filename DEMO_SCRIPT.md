# Sakura N4 — 2–3 minute demo
Before recording, use the actually deployed version. The existing demo is
https://sakura-n4.vercel.app/. New static audio/full draft are not live until an
approved deployment. Do not demonstrate a source-only feature as if it were live.

**0:00–0:20 — Purpose**
“Sakura N4 helps me practise Japanese in small sessions. I developed this prototype
with generative AI for Oblig 3. It uses Norwegian and English explanations.”

**0:20–0:40 — Dashboard**
Set a future date and daily target in Settings. Return to Overview, show the
countdown and recorded progress. Explain that progress is local to this browser.

**0:40–1:05 — Learning**
Reveal 食, show katakana on’yomi/hiragana kun’yomi and example words. Mark Good.
Answer one grammar question and show the explanation. State the small curriculum
coverage honestly.

**1:05–1:30 — Listening (only after the new build is deployed and tested)**
Open Listening studio and play the shopping recording with native controls.
Reveal transcript, kana and Norwegian/English summaries. Explain that recordings
are original scripts synthesized with the licensed Open JTalk/Mei voice and do not
need an installed system voice. Do not claim audible playback unless actually heard.
If using the old live demo, show reading instead and explain its TTS limitation.

**1:30–2:15 — Exam**
Use Short Practice for a quick demonstration. Answer a question, refresh to show
recovery, confirm each section and submit. Show result explanations and history.
If the new build is deployed, also show Full Mock Exam 01's separate 28/29/28
question counts and 25/55/35-minute timers. It is an original full-length validation
draft, not an official or independently certified examination. You can submit
sections early for the video; do not claim to have sat all 115 minutes.

**2:15–2:40 — Technology and AI**
Show GitHub/PR and actual final test output. “React, TypeScript, Vite and Tailwind
provide the interface. Browser storage keeps the prototype usable without cloud
credentials. AI helped write code and original content, add tests and fix bugs.
The Vitest shutdown problem was resolved by updating the test dependency.”

**2:40–3:00 — Limitations**
Mention whichever checks are still pending: teacher/audio review, phone testing,
PWA installation and future cloud accounts. End on the dashboard. Use the real
demo/video URL in the submission. Never claim a merge, deployment or student
verification that has not occurred.
